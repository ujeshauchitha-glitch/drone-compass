## 2026-10-13 — Gate S1 PASSED; Gate S2 FAILED (study stopped at Stage 2, per PLAN.md section 7)
* **Gate S1 passed**: checks (a)–(f) pass for the verified H16 tensors (and for the recalled set R). Two independent yield implementations (eigenbasis vs Liouville) agree to ~1e-15 on 200 directions. Primary anisotropy ΔΦ = 0.2057 (Φ from 0.3345 to 0.5402), far above the 1e-3 threshold. Richer ASSUMED models dilute it to ≈0.01 (R2, R3); relaxation at 1e7/s reduces it to ≈1.5e-3 (scan-based). See `results/stage1_*.csv`.
* **Gate S2 FAILED as pre-registered** (`results/stage2_gate.json`): K3orth, ε = 1, Poisson only. Gate condition 1: ratios of MC median error to CRB-predicted median error at the three large-N points = 14541, 25858, 45982 (needed 0.5–2). Gate condition 2: log–log slope = −0.033 (needed −0.5 ± 0.1). Thresholds unchanged.
* **Cause (diagnosed, not a coding error)**: the N5/N10 tensors are diagonal in the molecular frame, so the molecule has exact π-rotation symmetries and Φ(±nx, ±ny, ±nz) = Φ(n) (checked numerically: mirror images give identical counts to 4e-13). Any element set whose rotations are axis permutations (K2, K3orth) inherits this, giving a 4-fold *mirror* ambiguity (up to ~90° apart) on top of the polarity ambiguity. The global ML estimator picks a mirror image about half the time (log-likelihood of the mirror image is equal to within noise), so MC medians are dominated by this and cannot approach the *local* CRB. The CRB itself is also singular at the three coordinate axes for this set.
* **Exploratory diagnostic (NOT a gate result, added after the failure, labelled as such)**: a fixed generic non-orthogonal K = 3 set (rotation vectors (0.3, 0.5, 0.2) and (−0.4, 0.2, 0.6) rad) removes the ambiguity: ratios 0.934, 0.898, 0.893, slope −0.483.
* Unit test `test_mle_recovers_truth_near_crb` was changed from a single K3orth assertion to two cases: K3orth is `xfail(strict=True)` documenting the ambiguity, K3generic must pass. This changes a unit test, not a pre-registered gate threshold or gate configuration.
* **Decision needed from the study owner before continuing**: either (A) amend PLAN.md with a clearly labelled post-hoc amendment (Gate S2 evaluated on the optimised/generic K = 3 set, K3orth reported as a failed baseline and a core negative finding), or (B) stop here and report. Nothing past Stage 2 has been run.

* **Design result** (`results/stage2_design.json`): K = 3 restarts J_ref = 3.998, 4.788, 1.420 → restart 1 selected (design grid); confirmation grid J_ref = 2.26 nats (< 10 nats, i.e. some >10° pairs are only moderately distinguishable at N = 10⁸). * **BUG (estimator), found by a diagnostic after Gate S2′ had passed**: `Sensor.mle` refined only the single best grid point. At very large N the likelihood peak is much narrower than the grid spacing (~2.5°), so the best grid point can lie in a wrong basin. Symptom: ambiguity-failure rate (error > 10°) plateaued at 2–3 % even at N = 10¹¹ for the selected set. Diagnosis: in all 6 failures at N = 10¹⁰ the log-likelihood at the estimate was lower than at the truth (by 183 to 8.3×10⁴), and multi-start refinement recovered the truth to 0.0°. So these were estimator failures, not physical ambiguity (contrast with K3orth, where the mirror image has equal likelihood).
* **Fix**: refine up to 4 well-separated (> 8°) top grid candidates and keep the best. After the fix, failure rate at N = 10¹⁰ and 10⁸ is 0 of 300 for the selected set. Regression test added (`test_mle_no_wrong_basin_at_large_N`).

## 2026-10-13 (Stage 3) — main grid done; pre-registered answer; exploratory additions (logged before they run)
* **Main grid finished** (462 configurations, 36 min, 2 workers; `results/stage3_summary.csv`, `stage3_yaw_errors.csv.gz`). **Pre-registered decision question (A2.3): 0 of 390 C/D configurations reduce yaw RMSE by ≥ 20 % at both t = 60 s and t = 600 s with a paired-bootstrap CI lower bound > 0 relative to arm B → NO.** At t = 60 s alone no configuration exceeds 3.5 %; at t = 600 s alone 20 of 390 meet the criterion (all arm C, all at σ_mag ∈ {0.1, 0.5} µT).
* **Important caveat found in the results:** arm B (and C, D) are strongly inconsistent in the main grid because the pre-registered filter noise does not include the always-present 1 % soft-iron distortion: arm B mid-gyro NEES at σ_d = 0 is 480 / 441 / 183 at 60 / 300 / 600 s (a consistent filter has ≈ 6), and 1779 at 600 s with σ_mag = 0.1 µT. The yaw error of every magnetic arm is therefore dominated by an unmodelled common systematic error, B is an over-confident, weak baseline, and the t = 600 s "wins" of C (including at σ_mag = 0.1 µT, where MEMS noise is far below the radical-pair noise) are artefacts of C trusting the same biased measurement less, not evidence of radical-pair merit. Reported as found; the pre-registered answer stands.
* **Exploratory additions (EXPLORATORY; no gate or decision depends on them):** (E1) "tuned" filters: soft-iron per-axis std 0.5 µT (≈ 0.01·|B|, the realised error level) added to the measurement variance of both magnetic sensors (arm B: + 0.5² µT²; arms C, D: + (0.5/|B|)² rad²) — implemented as the optional config key `si_R_um` (default 0 = pre-registered behaviour, verified by the unchanged regression tests); mid gyro, dip 45°, σ_mag ∈ {0.1, 0.5, 2} µT, σ_d ∈ {0, 2, 10} µT, arms B, C, D, σ_rp as before. (E2) no soft iron at all (`soft_iron=False`, pre-registered R) at σ_mag = 0.5 µT, same other settings. Purpose: separate the effect of sensor noise from the effect of an unmodelled systematic, which a hostile reviewer would raise.
* **Exploratory results (E1 and E2, `results/stage3_exploratory_tuned.csv`):** criterion met in 0 of 90 (E1, soft-iron variance added to R) and 0 of 30 (E2, no soft iron). **E1 did not restore filter consistency** (arm B NEES still 118–462 at σ_d = 0, 44–139 at σ_mag = 2 µT) because the soft-iron error is a constant body-frame bias, not white noise, so inflating R cannot make the filter consistent; a fair baseline would estimate the distortion online (bias-state augmentation), which is not modelled here. **E2 is the one clean noise-only case** (σ_d = 0, filter consistent: NEES 5.9 / 5.6 / 6.3): arm C with σ_rp = 0.3° (about 2× better than the 0.5 µT MEMS magnetometer's ≈ 0.57° per axis) gives yaw-RMSE reductions of only 3.3 % (t = 60 s) and 10.7 % (t = 600 s); arm D 5.1 % / 11.5 %; C is worse than B for σ_rp ≥ 1°. Any disturbance (σ_d ≥ 2 µT) makes NEES 224–1150 for every magnetic arm even without soft iron (the filter treats a non-white, shared disturbance as white).
* **Other Stage 3 results:** observability (`results/stage3_observability.json`): arm A numerical rank 5 (single null direction = yaw), arms B, C, D rank 6 in hover and turn windows at dips 15°/45°/66° — the axis-only channel loses nothing locally; information-implied yaw std: B 0.044°/0.113°/0.244° vs C 0.066°/0.131°/0.271° (hover, dip 15°/45°/66°, σ_mag = 0.5 µT, σ_rp = 1°).
